## Commit Message:
```
fix(backup): accept even-length hex keys >=32, keep 64-hex backward-compatible

from_hex_key hard-rejected any key whose length was not exactly 64, while
deploy-prod.sh already allowed {32,}. Relax the parser to accept any
even-length hex key of >=32 chars:
- 64-hex (32-byte) keys stay on the raw path (byte-identical to legacy),
  so existing production backups still decrypt.
- other lengths derive a 32-byte key via
  Sha256(b"commoncal/backup-key/v1\0" || decoded).
- odd length, <32 chars, and non-hex are rejected with a clear InvalidKey
  error.

Aligns deploy-prod.sh and bootstrap-production.sh gates to the same
even-hex>=32 contract and documents it in DEPLOYMENT.md.

Tests: 32/48/64-hex round-trips, exhaustive 256-byte raw-path byte-identity,
derived-path KDF-output pin, boundary/negative cases, CLI round-trip.
```
